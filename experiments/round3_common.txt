ROUND-3 RULES FOR ALL AGENTS (resource-constrained box)
- Box: 4 CPU cores, 15 GB RAM, ~7 GB free disk, no GPU, no LLM. HF_HUB_OFFLINE=1: use only models already in the HF cache (e5-small, e5-base, bge-m3, bge-reranker-v2-m3, mmarco-MiniLM, potion). Do not download models > 300 MB.
- Do NOT create a new torch venv (2-3 GB each). Put your code in your experiment folder but run it with an existing venv, e.g. `cd experiments/17_lex_rerank && uv run python ../NN_xxx/script.py` (17_lex_rerank and 14_ltr_fusion have torch, sentence-transformers, bm25s, numpy, scipy, lightgbm; 13_lexical_upgrades has bm25s + rag_eval). If you need a pure-python package, add it to that folder's pyproject with `uv add`.
- Exactly ONE torch/embedding/reranking process on the box at any time: wrap every such command in `flock /home/user/Tax-on-web4AI/experiments/.torch.lock <command>` and set OMP_NUM_THREADS=4. BM25/numpy-only jobs need no lock. Reuse existing embedding caches (experiments/data/emb_cache; e5-small chunks for C from exp 09; reranker score caches in 14_ltr_fusion/cache and 17_lex_rerank/cache) whenever the texts are identical.
- Budget: reranking costs ~1 s per (question, chunk) pair; keep total reranking under ~2 hours for your experiment (e.g. 64 questions x 20 pairs x 4 variants).
- Protocol: rag_eval train/val split (Question.split, md5 parity); select configs on train only; report train / val / all MRR, H@1, R@10; save every run via rag_eval.save_result("NN_xxx", ...) so per-question ranks are stored; keep the 29/40/64 human questions untouched.
- Write experiments/NN_xxx/README.md (setup, tables, honest conclusion vs the bars: val A 0.736 / B 0.570 / C 0.665; full-set A 0.703 / B 0.522 / C 0.703; round-2 best val C 0.688 (exp 17 lexical→bge@20), B 0.610 (exp 14)). Do not edit EXPERIMENTS.md, do not commit (the coordinator commits). Read experiments/EXPERIMENTS.md §3.10-3.11 and §4, and experiments/ideas/README.md §1-3 first.
- If the box is loaded (load average > 6) wait; never kill other agents' processes.
