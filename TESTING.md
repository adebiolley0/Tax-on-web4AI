# Testing Guide

## Running Tests

The repo is a **UV workspace** with three packages: `tax_search/`, `mcp_server/`, and `ingestion/`. Tests live in the `ingestion` package and are discoverable once the workspace is synced. No `PYTHONPATH` needed.

```bash
# One-time: install all workspace packages (tax-search, tax-mcp-server, tax-ingestion)
uv sync --all-packages
```

Then run pytest from the repo root:

```bash
# Run all tests
uv run python -m pytest ingestion/tests/ -v

# Run a specific test file
uv run python -m pytest ingestion/tests/test_content_cleaner.py -v

# Run semantic search validation (slower — embeds documents; ~10 min on CPU)
uv run python -m pytest ingestion/tests/test_semantic_search_validation.py -v --tb=short

# Run fast tests only (skip semantic-search validation and benchmarks)
uv run python -m pytest ingestion/tests/ -v \
    --ignore=ingestion/tests/test_semantic_search_validation.py \
    --ignore=ingestion/tests/benchmarks
```

Syntax-only check (no dependencies needed):
```bash
uv run python -m py_compile ingestion/src/tax_ingestion/storage/content_cleaner.py
```

## Search Strategy Benchmarks

The benchmark suite (`ingestion/tests/benchmarks/test_search_strategies.py`) compares 25 Qdrant search pipeline configurations on the same validation dataset.

### Running benchmarks

```bash
# Full grid search (prints leaderboard sorted by MRR)
uv run python -m pytest ingestion/tests/benchmarks/test_search_strategies.py -v -s

# Run only the leaderboard output (skips assertion tests)
uv run python -m pytest ingestion/tests/benchmarks/test_search_strategies.py -v -s -k leaderboard
```

The `-s` flag is important — it enables the printed leaderboard table and per-question rank breakdown.

### How it works

1. **Index once**: all 21 validation documents are chunked, embedded, and stored in a single in-memory Qdrant collection with three vector types: dense (384-dim MiniLM), sparse (BM25), and ColBERT multi-vectors (token-level embeddings).
2. **Search many times**: each of the 25 pipeline configurations runs all 21 questions against that same collection.
3. **Compare**: metrics are computed per-config and displayed in a sorted leaderboard.

### Pipeline configurations tested

The grid search covers all valid combinations of:

| Axis | Options |
|------|---------|
| **Retrieval** | dense / sparse (BM25) / hybrid (dense+sparse) |
| **Fusion** | RRF (Reciprocal Rank Fusion) / DBSF (Distribution-Based Score Fusion) |
| **Prefetch depth** | 20 / 50 / 100 candidates |
| **Reranking** | none / ColBERT multi-vector MaxSim (20–100 candidates) |
| **Grouping** | none / `group_by document_id` (group_size 1–5) |
| **Multi-stage** | e.g. hybrid → ColBERT → grouped (nested prefetch) |

Configurations are generated by `generate_grid_configs()` in `tax_search/src/tax_search/search.py`.

### Key modules

- **`tax_search/src/tax_search/search.py`** — search strategies and composable pipeline infrastructure:
  - `PipelineConfig` — declarative dataclass describing a pipeline
  - `FullVectorStore` — collection with dense + sparse + ColBERT vectors
  - `execute_pipeline()` — builds nested Qdrant query trees from a config
  - `generate_grid_configs()` — enumerates all valid configurations
  - `BM25Encoder` — French-aware BM25 sparse vector encoder

### Metrics

| Metric | Description |
|--------|-------------|
| MRR | Mean Reciprocal Rank — reciprocal of rank of first expected doc, averaged |
| nDCG@5 | Normalized DCG at rank 5 (deduplicated by document_id) |
| R@10 | Recall at 10 — fraction of questions with expected doc in top 10 |
| MAP@10 | Mean Average Precision at 10 (deduplicated by document_id) |

### Output

Results are printed as a leaderboard table and saved to `ingestion/validation_dataset/benchmark_results.json`.

## Semantic Search Validation Dataset

Located in `ingestion/validation_dataset/`:

```
ingestion/validation_dataset/
├── md/                        # Markdown documents (substantive circulaires & FAQs)
├── sample_extra/              # Extra documents used to verify cleaning patterns
├── manifest.json              # Metadata for all downloaded documents
├── questions.json             # Test questions with ground truth
├── search_results_report.json # Latest search results (auto-generated)
└── benchmark_results.json     # Grid search benchmark results (auto-generated)
```

### What the validation test does

1. **Ingests** all documents from `ingestion/validation_dataset/md/` into an in-memory Qdrant instance
2. Applies the **content cleaner** (removes index sections, boilerplate, ToC)
3. **Chunks** documents (1500 char max, 200 char overlap)
4. **Embeds** chunks with `paraphrase-multilingual-MiniLM-L12-v2` (384D) — overridable via the `EMBEDDING_MODEL` env var
5. Runs all tax-return questions in `questions.json` and checks that expected documents rank in the top results
6. Reports **aggregate metrics**: Recall@10, MRR, nDCG@5, average cosine similarity scores

### Document selection criteria

Only documents with **legal value or substantive informational content** should be in `validation_dataset/md/`. See `MYFIN_ARBORESCENCE.md` § "Classification" and `AGENTS.md` § "Document filtering policy" for the authoritative rules.

| Include ✅ | Exclude ❌ |
|-----------|-----------|
| Circulaires (binding administrative interpretations) | **Aperçu documentaire** / "Commentaire CIR 92" index pages (list references only, no substantive text) |
| FAQs with developed substantive content | Table-of-contents and navigation documents |
| Legislation text (CIR 92, AR/CIR 92, regional codes) | "Cours professionnels" (training materials, not legally binding) |
| Royal decrees (arrêtés royaux, legally binding) | "Compétences et formulaires" (portal navigation pages) |
| Advance rulings (décisions anticipées) | Help/navigation pages, Guide utilisateur |
| Parliamentary questions (interpretive value) | Mémento fiscal (didactic summary, not citable) |
| Jurisprudence (court decisions) | Working Papers, Briefing Notes |

**Note on "Commentaire CIR 92" pages:** Fisconet+ exposes one index page per CIR 92 article under
"Commentaire CIR 92 (aperçu documentaire)". These pages merely list which circulars, decisions and
parliamentary questions relate to each article. The actual commentary text is absent (marked `N/A`).
These documents must NOT be ingested. The moved copies in `validation_dataset/sample_extra/` serve
as negative-example fixtures for content-cleaner tests.

### Ground truth format (`questions.json`)

```json
[
  {
    "id": "Q1",
    "question": "French-language question a taxpayer might ask",
    "topic": "snake_case_topic_name",
    "expected_docs": ["doc_id_1", "doc_id_2"],
    "secondary_docs": ["doc_id_3"],
    "expected_keywords": ["term1", "term2"]
  }
]
```

- `expected_docs`: Documents that MUST appear in top-10 results (primary relevance)
- `secondary_docs`: Documents that may also appear (acceptable but not required)
- `expected_keywords`: Terms that should be present in the relevant document content

### Known limitations (marked `xfail`)

| Question | Issue | Fix |
|----------|-------|-----|
| Q5 (charitable donations) | Synonym gap: query uses "dons", doc uses "libéralités" | MiniLM cannot bridge French synonym gap; needs query expansion or a denser model |

### Adding new documents

1. Find the document GUID on Fisconet+ (use `POST /search` endpoint)
2. Add it to `ingestion/scripts/download_validation_pdfs.py` CANDIDATES list
3. Run the download script: `uv run python ingestion/scripts/download_validation_pdfs.py`
4. Update `ingestion/validation_dataset/questions.json` ground truth if needed
5. Re-run validation: `uv run python -m pytest ingestion/tests/test_semantic_search_validation.py -v`

## Content Cleaner Tests (`test_content_cleaner.py`)

Unit tests for each cleaning function using synthetic inputs that mirror real Fisconet+ document patterns:

- `TestStripIndexSections` — Verifies removal of `## Législation`, `## Circulaires`, etc. while preserving document titles and `## Commentaire` sections
- `TestStripToc` — Table-of-contents removal
- `TestStripBoilerplate` — SPF headers, Numac, signatures, metadata lines
- `TestStripDecreePreamble` — Royal decree formulaic blocks (Vu..., Considérant que...)
- `TestStripKeywordLines` — Semicolon-separated tag lines
- `TestNormalization` — Whitespace collapsing
- `TestCleanForIndexing` — Integration tests for the full pipeline

## Key Metrics

| Metric | Threshold | Description |
|--------|-----------|-------------|
| Recall@10 | >= 80% | Fraction of scorable questions with expected doc in top-10 |
| MRR | >= 0.3 | Mean Reciprocal Rank across all questions |
| nDCG@5 | >= 0.4 | Normalized Discounted Cumulative Gain at rank 5 |
| Avg best-match score | >= 0.35 | Average cosine similarity of best expected-doc hit |
| Top score per question | >= 0.3 | Each question's #1 result must exceed this |

**Note:** These thresholds were calibrated against the original 21-question dataset and may not be met by the default MiniLM-dense baseline on the expanded (31+ questions) set. Stronger retrieval strategies (BGE-M3, hybrid + ColBERT reranking from the benchmark suite) are required to clear the bar — see `benchmark_results.json`.
